# 음성 결과 수신 계약·검증·호환 선행 구현

- 날짜 · 2026-11-17
- 작성자 · 박찬원
- 도구 · Codex
- 목적 · 음성 결과의 조건·사유·근거 발화·상담·재연락·종료 정보를 받는 백엔드 기반과 팀원 인계 자료 준비

## 프롬프트 · 사용자 요구 요약

> 최신 Git을 확인하고 음성 협의안의 선택 필드를 받는 수신 계약·입력 검증·기존 결과 호환 처리를 선행 구현한다. 발화 예시의 라벨과 판정 근거를 유지하고, 작업 목적을 간결하게 기록한다. 검사 후 병합하지 않은 PR로 남기며, 구현 내용과 백엔드 팀원이 이어서 맡을 저장·조회 작업의 전달문을 작성한다.

## 구현 내용

- condition·reason_text·evidence_turns·redirect, consult, turn_no, 재연락 사유/원문, end_reason 수신 모델
- 필드 길이·상태 조합·시간대·동일 통화 근거 참조·중복/유효하지 않은 값 검증
- 기존 워커 생략/null 결과의 직렬화·재전송 해시, 구형 검토 요청의 추가 정보 보존
- 기존 전체 결과 JSON 경로의 신규 값 보존 확인, 계약 명세·요청 예시·후속 저장/조회 분담 문서

## 작업 경계

질문별 추가 컬럼/새 근거 조회·권한 API·프론트/워커 반영은 후속이다. 끊김 자동 재시도·재확인 통화·남은 질문 재통화 정책은 추가하지 않는다. main 병합·배포·공동 DB 변경·실제 전화·외부 LLM 호출은 수행하지 않는다.

## 결과 활용

코드와 검증 사례를 검토용 PR로 공유하고, 다른 백엔드 팀원은 이 계약을 기준으로 저장 구조·근거 조회·권한·교정 범위를 이어서 보완한다.
