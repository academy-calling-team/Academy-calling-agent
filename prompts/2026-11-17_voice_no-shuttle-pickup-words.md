# 셔틀·픽업 대신 등원·하원 차량으로 묻기 (11/17)

- 날짜: 2026-11-17
- 작성자: 김규림
- 사용한 도구: Claude (Claude Code)
- 목적: 강유준 정리(11/16)를 반영해, 상담원·판정에서 '셔틀', '픽업'을 쓰지 않고 방향과 장소를 넣은 '등원 차량', '하원 차량'으로 맞춘다. 셔틀은 등원인지 하원인지, 픽업은 데리러 오는지 데려다주는지가 사람마다 달라 학원 답을 판정할 수 없다.

## 프롬프트

```
(강유준 메시지: 시험 세트·노션은 고쳤고, 남은 곳은 음성 상담 프롬프트와 위치가 없을 때의 기본 질문 문장. 직접 고칠지 정해 달라)
(강유준 메시지: 화면 이름만 '등원 차량', '하원 차량'으로 바꾸고 코드 값 shuttle·pickup은 유지하자)
계속
```

## 결과를 어떻게 썼는지

- Claude가 강유준이 짚은 두 곳을 고쳤다.
  - `voice/call_worker/extract.py`: 위치가 없을 때 쓰는 기본 질문 문장
  - `voice/prompts/service_agent_prompt.txt`: '셔틀', '픽업' 금지 한 줄. 강유준이 제안한 문장 그대로
- Claude가 추가로 찾은 한 곳도 고쳤다. `voice/call_worker/llm_judge.py`의 판정 질문 설명이 여전히 '통학 차량이 있는지', '수업 후 픽업'이었다. 방향을 넣고 '반대 방향만 된다는 답은 no'를 붙였다. 판정 판을 judge-v3.3-direction으로 올렸다.
- 코드 값(shuttle, pickup)은 바꾸지 않았다. 계약·DB·시험 세트에 모두 들어가 있고, 학부모와 학원은 코드 값을 보지 않는다(강유준 의견에 동의).
- 테스트 중 발견: #54의 Asia/Seoul 시간대 때문에 Windows에서는 main에서도 워커 테스트 13개가 실패했다(tzdata 없음, 리눅스 CI는 통과). `voice/requirements.txt`에 Windows용 tzdata를 추가했다.
- 실제 서비스 에이전트 반영(`setup_service_agent.py update`)은 이 PR 병합 뒤 김규림이 결정한다.
- 화면 이름(백엔드 '통학 차량'·'픽업', 프론트 '셔틀 운행'·'픽업 가능 여부')은 백엔드·프론트 담당이라 고치지 않았다.
