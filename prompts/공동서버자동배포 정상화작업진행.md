“프론트 담당이 수정 완료 후 push한 최신 코드를 기준으로 수정하고, 기존 작업에 덧붙이는 기록을 prompts에 남긴다. PR 전에 시험을 실행해 문제를 확인하고 올린다. 문제 원인 분석과 해결 방법도 함께 기술한다.”

시작 main은 `f6f03d8041625b6e3ba26d1e713aa9d330672cbe`이다. 딩옌의 React·Vite·TypeScript 리팩토링과 화면 구성을 유지한다. 기존 사용자 PC의 Next.js 작업 사본·로컬 수정·개인 설정은 보존하고 별도 작업 사본과 `fix/shared-autodeploy-normalize` 브랜치에서 수정했다.

## 원인 분석

1. **자동 검사와 리팩토링 결과 불일치.** workflow는 `npm run typecheck`와 약관 동의·실통화 확인 시험 두 파일을 호출하지만, 새 package.json에는 typecheck가 없고 시험 파일도 삭제됐다. 프론트 빌드 자체는 성공해도 검사 단계에서 종료된다. deploy는 checks 성공이 선행조건이라 실행되지 않았다. 기존 실패 실행은 GitHub Actions `40092558689`.
2. **인증 초기화와 목록 조회 경합.** 홈·내 상담·상세 hook이 인증 확인 전에 요청한다. AuthProvider 초기화가 session epoch를 변경하면 목록의 정상 응답도 오래된 세션으로 판정해 버린다. 인증 준비 완료 후 다시 요청하는 연결이 없고, 비어 있는 목록은 polling 조건도 만족하지 않아 로딩이 유지된다. Edge에서 정상 계정 응답 150~200ms·목록 응답 300~450ms의 통제된 응답으로 재현했다.
3. **Windows 실행 구성 불일치.** 기존 외부 실행 파일은 Next.js 실행 파일과 3000번 주소를 확인한다. 새 프론트는 Vite·5173번이다. 저장소의 소스만 교체하면 기존 실행 파일로 기동할 수 없다.

## 해결 방법과 변경 파일

- `frontend/package.json`, lock: 기존 TypeScript 설정을 사용하는 typecheck와 npm test를 추가하고 브라우저 시험에 필요한 Playwright를 개발 의존성으로 고정했다.
- `frontend/scripts/auth-consent.test.mjs`: 새 서버 중계 함수를 직접 실행해 동의 누락·false·문자열 차단, boolean 전달, 로그인 쿠키, 다른 출처 차단, 인증된 소유자와 요청키 전달을 확인한다. 외부 fetch는 가짜 응답으로 교체한다.
- `frontend/scripts/real-call-form.test.mjs`: 실제 React 화면을 Vite와 브라우저로 실행한다. 홈·내 상담·상세 직접 진입과 새로고침, 회원가입 동의·로그인 후 목록 표시, 수신자 확인 없는 실제 시험 요청 차단, 준비 중 학원 차단, 확인 후 1회 접수를 검증한다. 모든 API 응답은 시험용으로 가로채므로 실제 발신·공유 DB 쓰기는 없다.
- `.github/workflows/shared-api-deploy.yml`: 새 typecheck·npm test·빌드 순서로 검사하며 Linux Chromium을 설치한다. 기존 일회용 MySQL·Redis 백엔드 전체 검사와 음성 두 워커 검사, checks 성공 후 main 전용 배포 조건을 유지한다. PR에서 서버 배포는 실행하지 않는다.
- `frontend/src/hooks/useInquiries.ts`: 인증 준비와 사용자 식별 후 목록·상세를 요청한다. 세션/사용자 변경 시 다시 조회하고 로그아웃·준비 중에는 이전 목록·상세를 비운다. 효과 정리 시 요청 버전을 증가시켜 이전 화면·페이지·계정의 응답을 무효화한다. 미로그인 상세는 로그인 필요 오류로 종료한다.
- `frontend/프론트_실행.cmd`: Node/npm·Vite·개인 설정 존재를 확인하고 현재 폴더에서 npm run dev -- --open을 실행한다. 한국어 UTF-8·CRLF 파일이며 실행 중 Ctrl+C로 종료한다. 개인 환경 파일 내용은 수정하지 않는다.
- `frontend/vite.config.ts`: 개발 5173·미리보기 4173 포트 점유 시 다른 포트로 자동 이동하지 않게 설정한다.
- `frontend/README.md`: 새 실행 파일·검사·주소·설정 보존과 배포 범위를 안내한다.

## PR 전 로컬 검증

- npm 의존성 설치 성공, typecheck 성공, Vite 정식 빌드 성공.
- Node·실제 Edge 브라우저를 사용한 프론트 계약/회귀 **13개 통과**.
- 백엔드 portable **14개**, 음성 목업 **30개**, 실통화 워커 **37개 통과**. Python 합계 81개. 임시 SQLite·가짜 제공업체 기반 범위이며 실제 통화 시험이 아니다.
- Python 세 범위를 한 pytest 프로세스에서 실행한 최초 시도는 두 모듈의 worker 이름 충돌로 수집에 실패했다. workflow와 같이 별도 프로세스로 다시 실행해 모두 통과했다. 이 수집 오류를 제품 결함 수정이나 전체 통합 시험 성공으로 기록하지 않는다.
- 이번 PC에서는 MySQL·Redis 전체 백엔드132개를 재실행하지 않았다. 원격 PR에서 기존 CI의 일회용 MySQL·Redis 전체 검사를 별도로 확인한다.
- DB 스키마·API 계약·백엔드 실행 코드는 변경하지 않는다. 기존 실통화 1회·허용 계정/번호·서버 활성화 조건도 유지한다.

## 반영 범위와 완료 판정

PR 검사 성공과 main 병합 후 서버 배포 성공은 별개다. 브랜치 업로드·PR 단계에서는 운영 버전이 바뀌지 않는다. main 병합 후 자동배포 성공과 `/shared/ready`, `/shared/version`의 해당 커밋을 확인해야 서버 배포까지 정상화 완료다. 프론트 화면 AWS 게시나 각 팀원 PC 소스 갱신은 이 자동배포의 대상이 아니다.

기존 설계·리팩토링 기록은 보존한다. 노션·팀원 메시지·실전화·DB 변경은 수행하지 않는다.
