```
## 2. 주제 (하나만 남기고 지울 것. 기본은 C)
- A: 학원 문의 대행 음성 에이전트의 시스템 설계와, 같은 음성 모델을 두 음성 플랫폼에 올렸을 때의 응답 지연, 정확도, 음성 끊김 비교
- B: 상담 항목별 상태 관리로 여러 차례 통화에서 정보 수집 정확도를 높이고 반복 질문을 줄이는 방법 (실험 미실시)
- C: A를 본문으로 쓰고, B는 '제안 구조와 향후 과제' 절에 짧게 넣는다. B의 효과는 주장하지 않는다

## 3. 시스템 (사실)
배경: 맞벌이 학부모는 저녁에만 통화할 수 있는데 그 시간에 학원은 수업 중이라 간단한 문의도 며칠씩 밀린다. 학원이 전화를 받기 쉬운 시간에 AI가 대신 전화해 답을 받고 문의자별로 저장하는 서비스다. 기업 멘토의 요구는 "UI보다 데이터가 정확히 저장되는 것"이다.

처리 흐름:
1. 학부모가 웹에서 학원, 학년, 과목, 수준과 객관식 문의 항목(빈자리, 수업 시간, 상담 가능 시간 등)을 고른다
2. 백엔드(FastAPI, MySQL, Redis)가 학원 운영 시간, 대기 순서, 동시 통화 수를 보고 발신 작업을 음성 워커에 넘긴다. 부재중이면 5분 뒤 다시 건다
3. 음성 워커가 음성 플랫폼으로 학원에 국내 070 번호로 전화한다. AI는 첫인사에서 "AI 상담원"과 "이 통화는 녹음됩니다"를 알린 뒤 항목별로 질문한다
4. 통화 결과를 질문별 결과(JSON)로 정리해 백엔드에 보낸다. 질문마다 답을 받았는지(answered), 예·아니오(yes_no), 못 받은 이유(unknown, refused, not_asked), 수업 시간 텍스트, 상담 가능 시간, 재통화 요청 여부를 담는다. 못 물었거나 답을 못 받은 질문도 빠뜨리지 않고, 실제로 확인하지 않은 값은 만들지 않는다
5. 백엔드가 결과를 문의와 문의자에 연결해 저장하고, 학부모는 화면에서 '아니오'와 '미확인'을 구분해 본다

구현 상태 (2026-10-14):
- 백엔드 개발 API 0.4.0, DB 테이블 21개, 자동 테스트 139개 통과. 같은 문의를 다시 보내면 Idempotency-Key로 한 건만 처리하고, 확정 거절(409 등)은 다시 보내지 않으며, 600초 넘어 도착한 결과는 저장만 하고 반영하지 않는다
- 목업 음성 워커로 백엔드와 실제 HTTP 왕복을 확인했다(문의 등록부터 결과 조회, 부재중 뒤 재발신). 실제 음성 플랫폼과 백엔드의 연결은 다음 단계다
- 웹 화면은 회원가입, 문의 접수, 처리 상태, 결과 조회를 지원한다. AWS에 개발 서버를 구축했다
- 설계 원칙: 음성 플랫폼마다 다른 코드는 음성 워커 안에만 둬서, 플랫폼을 바꿔도 백엔드와 화면은 바뀌지 않는다

## 4. 실험 (사실, 숫자를 바꾸지 말 것)
목적: 같은 음성 모델을 두 플랫폼에 올렸을 때 응답 지연, 정확도, 음질이 어떻게 다른지 본다.

조건 (2026-10-13):
- 플랫폼 1: ClawOps 자체 음성 에이전트 (국내 070 회선, 에이전트는 GCP 서울 리전)
- 플랫폼 2: Vapi (미국 플랫폼, ClawOps 070 회선을 SIP 직접연결로 빌려 씀)
- 같은 모델 OpenAI GPT-Live(gpt-live-1), 추론 강도 none, 음성 marin, 같은 프롬프트(질문 3개: 빈자리, 수업 시간, 상담), 같은 학원 역할 대본. 학원 역할은 연구자 한 명이 휴대폰으로 받음
- 플랫폼마다 7통 (대본 A~E 5통과 재통화 2통). 끼어들기 대본 H는 지연 통계에서 뺌
- 응답 지연 = 사람 말이 끝난 시점부터 AI 첫 소리까지. 두 플랫폼 모두 ClawOps 서버 녹음(같은 지점)으로 쟀고, 휴대폰망 구간은 포함되지 않는다
- 자동 분석: silero VAD로 말소리 구간, ERes2Net 화자 임베딩, Whisper(turbo)로 전사한 뒤 대본과 말투로 화자를 다시 판정. 말소리 기준 −50dBFS
- 검증: 연구자가 파형 뷰어로 녹음 16개를 직접 들으며 사람과 AI를 나눠 다시 쟀다

결과:

통계:
- 중앙값 차이 0.18초, 부트스트랩 95% 구간 0.06~0.30초, Mann-Whitney 검정 p<0.001. 대본 A~E만 보면 0.14초(구간 −0.02~0.28초). 한 통화 안의 응답은 서로 독립이 아니어서 실제 불확실성은 더 크다
- 대본 A~E 분위수별 차이: p10 +0.11, p25 +0.14, p50 +0.14, p75 +0.25, p90 +0.25초. 분포 전체가 밀려 있다
- 직접 측정과 자동 분석: 16통 중 14통에서 응답 개수와 순서가 같았다. 짝이 맞는 84쌍에서 직접 값이 평균 0.04초 짧은데, 뷰어가 −60dB 기준이라 말 끝 숨소리까지 말로 잡았기 때문이다(7곳 재계산으로 확인). 자동 분석이 잘못 잡은 것으로 보이는 2곳은 재확인 중이다. 응답이 1.5초 근처에 몰려 있어서 '1.5초 넘은 비율'은 측정 기준에 민감하므로 중앙값과 p95를 주 지표로 쓴다

원인 분석 (측정값, 플랫폼이 알려 준 값, 우리가 계산한 추정을 문장에서 구분할 것):
- 네트워크로는 설명되지 않는다. Vapi는 미국을 거쳐 약 90ms 더 먼데도 더 빠르다
- ClawOps 답변(2026-10-14 고객지원 메일): GPT-Live 모드에서는 모델이 말 끝을 직접 판단하고 별도의 음성 감지 대기가 없다. 입력 음성을 100ms 단위로 묶어 모델에 보내고, 출력 음성은 100ms(늦으면 최대 200ms)를 쌓은 뒤 내보낸다. 우리 통화에서 출력 대기는 응답당 평균 약 80ms였다(ClawOps 측정)
- 입력 묶음 대기: 말이 끝나는 시점이 100ms 묶음 안에 고르게 떨어지므로 평균 약 50ms (계산한 추정)
- Vapi는 이 값을 공개하지 않는다. 전화 음성 RTP의 표준 묶음 20ms(RFC 3551)라면 입력 대기는 평균 약 10ms이고, Vapi에서만 끊김이 12번 나온 것으로 보아 출력 버퍼는 거의 없다고 추정한다
- 합치면 ClawOps가 약 0.12초(80ms + 40ms) 더 쓰며, 대본 A~E 중앙값 차이 0.14초의 대부분이다. 나머지 일부는 Vapi에서 모델이 사람 말이 끝나기 직전에 말을 시작한 경우(1.2초 미만 응답 Vapi 7개, ClawOps 1개)로 설명된다
- 해석: 출력 버퍼를 두면 느리지만 끊기지 않고, 줄이면 빠르지만 끊긴다. 응답 지연과 음질은 같은 설계 선택의 맞교환이다

한계: 한 사람이 하루 동안 플랫폼마다 7통을 걸어 응답이 50개 안팎이다. 서버 녹음이라 휴대폰망 구간이 빠져 있다. 모노 녹음이라 화자 판정에 전사와 대본을 썼다. GPT-Live는 말 끝 판정, 이해, 음성 생성을 한 모델이 해서 구간별로 지연을 나눌 수 없다. Vapi에서 외부 SIP 트렁크로 GPT-Live를 쓰는 조합은 Vapi 문서에 없는 구성이다. 목표 응답 시간 1.5초는 두 플랫폼 모두 p95 기준으로 맞추지 못했다.

## 5. 제안 구조 B (C를 쓸 때만, 실험 결과 없음)
상담 항목마다 미확인, 일부 확인, 추가 확인 필요, 확인 완료 상태와 답변 근거(통화 날짜, 대화 내용)를 저장하고, 다음 통화에서는 해결되지 않은 항목을 먼저 묻는다. 정보가 바뀌거나 이전 답과 다르면 다시 확인한다. 검증 설계는 세 방식 비교다: 가(학생 정보와 상담 목표만), 나(이전 통화 전체 기록), 다(항목별 상태와 근거). 평가 지표는 정확한 정보 수집률, 상담 완료율, 불필요한 반복 질문률, 답변 정확도, 효율(대화 횟수, 통화 시간, 비용)이다. 현재 결과 형식에 질문별 답, 못 받은 이유, 재통화 요청이 이미 있어서 이 구조로 확장할 기반이 있다.
```

### 2. 7주차 회의 결과로 수정 (10/14)

```
앞에서 쓴 논문 초안을 아래 내용대로 고쳐 줘. 처음부터 다시 쓰지 말고 고칠 곳만 고친 뒤, 고친 전체 원고와 바꾼 곳 목록을 줘.

1. 주제 확정
- 주제는 A(학원 문의 대행 음성 에이전트의 시스템 설계와, 같은 음성 모델을 두 플랫폼에 올렸을 때의 비교)로 확정이다.
- B(항목별 상태 관리)는 실험하지 않는다. '향후 과제'에 두세 문장으로만 남기고 효과를 주장하는 문장은 모두 지운다.

2. 응답 지연 수치 교체 (가장 중요)
- 지연은 연구자가 파형 뷰어로 녹음을 들으며 사람과 AI 구간을 직접 나눠 잰 값만 쓴다. 자동 분석 수치와 자동/직접 비교 문단은 모두 지운다.
- 응답이 아닌 간격은 뺐다: AI가 되짚는 질문 뒤 답을 기다리지 않고 말을 이어 간 자리에 사람이 대답한 간격 4개(Vapi), AI 요약의 첫 음절을 사람 말로 잘못 나눈 것 1개(Vapi), 사람 말인지 불분명한 조각 1개(ClawOps).
- 결과 표를 아래로 바꾼다.
| 항목 | ClawOps | Vapi |
| 응답 수 | 49 | 44 |
| 평균 / 중앙값 | 1.63 / 1.57초 | 1.45 / 1.42초 |
| p90 / p95 / 최대 | 1.95 / 1.98 / 2.40초 | 1.67 / 1.78 / 2.12초 |
| 1.5초 넘은 응답 | 33 (67%) | 18 (41%) |
- 통계: 평균 차이 0.18초, p95 차이 0.20초, 중앙값 차이 0.15초(부트스트랩 95% 구간 0.02~0.29초), Mann-Whitney p<0.001. 대본 A~E만 보면 중앙값 차이 0.13초(구간 0.00~0.29초). 대본 A~E 분위수별 차이 p10 +0.09, p25 +0.16, p50 +0.13, p75 +0.23, p90 +0.27초. 1.2초 미만 응답은 Vapi 5개, ClawOps 1개. 통화 첫 응답의 중앙값은 ClawOps 1.62초, Vapi 1.33초.
- "Vapi에서 모델이 사람 말이 끝나기 직전에 말을 시작했다"는 설명은 지운다. 그 간격들은 응답이 아니어서 통계에서 뺐다.
- 버퍼 설명(ClawOps가 응답마다 약 0.12초 더 씀)은 그대로 두고, 비교 대상은 "대본 A~E 중앙값 차이 0.13초"로 쓴다.
- '1.5초 넘은 비율'은 말 끝을 조금만 다르게 잡아도 크게 바뀌므로 보조 지표로만 쓰고, 주 지표는 중앙값과 p95로 한다.
```
