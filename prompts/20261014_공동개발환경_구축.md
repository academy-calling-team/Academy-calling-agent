# 생성형 AI 사용 기록 · 백엔드와 프론트엔드 연동작업

- 작업일: 2026-10-14~15
- 사용 도구: OpenAI Codex
- 목적: 기존 프론트 화면을 공동 백엔드 API와 연결해 각자 PC에서 문의 접수·처리 상태·결과를 확인할 수 있도록 구성한다.

## 사용자 요청 요지

“각자 PC에서 개발하는 프론트·백엔드·음성이 공동 서버를 통해 연결되도록 환경을 구축해 달라. 백엔드와 프론트엔드 연동작업의 수정본을 별도 브랜치에 올리고, 팀원이 검토할 수 있도록 PR과 main 병합은 진행하지 말아 달라. 파트별 안내문은 별도 전달하므로 README의 중복 설명을 정리해 달라.”

위 문장은 여러 요청의 요지를 정리한 것으로 단일 발언의 원문 인용이 아니다.

## 수행 내용

- 기존 프론트를 표준 Next.js·Node 실행으로 정리하고 서버 환경변수로 공동 API를 연결했다.
- 로그인 쿠키·동일 출처 쓰기 검증을 유지하고 세션 전환 중 학원 목록 로딩 문제를 수정했다.
- 기존 화면에서 쓰지 않는 D1 초안 API와 ChatGPT 로그인 대체 경로는 Node 공동 구성에서 비활성화했다.
- 공동 API·공유 MySQL/Redis·서버 큐·음성 목업 워커를 연결해 화면 입력부터 결과 표시까지 시험했다.
- 서버용 목업 워커 Dockerfile과 실행 주소 환경변수를 추가했다. 백엔드 처리 코드·DB 구조·음성의 예시 답변 생성 로직은 이번 작업에서 바꾸지 않았다.
- 개인 격리 환경용 Compose와 서버 운영·배포 절차를 준비했다. README는 실행·명세 링크 중심으로 정리하고 파트별 전달 안내문은 업로드 대상에서 제외했다.
- 10/15 원격 main의 회의·논문 문서 변경을 검토 브랜치에 포함했다. 기존 문서와 다른 팀원 작업은 보존했다.

## 확인한 결과

- 10/14: PC 프론트 회원가입·로그인 → 공동 API → MySQL/Redis → 음성 목업 워커 → 완료 상태·질문별 답변 표시까지 확인했다.
- Node 최초 설치 구성·타입 검사·빌드·standalone·개발 모드, 계정 격리·CSRF·로그아웃·세션 목록 전환을 확인했다.
- 음성 목업 기존 테스트 30개 통과. 워커·큐 재시작 후 접수 기록과 후속 처리 보존을 확인했다.
- 10/15: 공동 DB의 w5_/w6_ 21테이블·125컬럼·키·인덱스·제약조건은 10/14 메타데이터와 동일했다. 데이터 행 수 증가는 시험 전 스냅샷과의 차이이며 특정 팀원의 수정으로 단정하지 않았다.
- 최종 README 정리 후 변경 목록·문서 링크·제외 파일을 확인했다. 실행 코드가 추가로 바뀌지 않아 기존 기능 검증을 그대로 적용했다.

## 검토 범위와 한계

- 실제 Vapi/ClawOps 발신은 연결하지 않았다. 화면에 나오는 답변은 목업이다.
- 현재 백엔드 HTTP 워커 경로는 is_mock=true만 지원한다. 실제 통화 전환에는 백엔드·음성의 추가 구현과 검증이 필요하다.
- 개인 Compose는 정적 검토만 했고 새 PC 기동은 검증하지 않았다. 각 팀원의 PC 실행 확인도 별도다.
- 기존 DB·서비스·담당 역할을 보존했다. 비밀번호·내부키·토큰·실제 DB 데이터·녹음은 업로드하지 않는다.
- 이번 전달은 backend/shared-collaboration-env 브랜치 업로드 범위다. PR 생성·main 병합·추가 서버 배포·노션 수정은 수행하지 않는다.
