# 백엔드 음성 워커 연동 개선

- 날짜: 2026-10-13
- 작성자: 박찬원
- 사용한 도구: OpenAI Codex
- 목적: 음성팀 협의 기준에 맞춘 백엔드 목업 연동 개선과 오류·제약 검증

## 프롬프트

사용자 요청을 목표·제약·검증 기준에 맞춰 정리한 작업용 프롬프트다. 원문 인용이 아니다.

음성팀과 협의한 연동 기준에 맞춰 백엔드를 개선하라. 기존 음성팀 코드를 변경하지 않고 백엔드의 요청 전달·오류 처리·결과 수신 동작을 검증하라.

### 구현 요구사항

1. 큐 실행기에 --worker-url 옵션을 추가하여 음성팀 목업 워커를 선택할 수 있도록 하라.
2. 외부 워커 사용 시 --simulate-results를 함께 실행하지 못하도록 하라.
3. 409를 비롯한 명확한 거절 응답을 접수 성공으로 처리하지 마라. 자동 재전송을 중단하고 실패 이유와 확인 필요 상태를 기록하라.
4. 타임아웃·연결 오류로 접수 여부가 불확실한 경우에만 동일 call_id로 접수 여부를 조회하라.
5. 재전송 시 동일 ID와 동일 본문을 유지하고 기존 중복 결과 처리 기능을 보존하라.
6. 결과 수신 시 대기 기한을 확인하라. 기한이 지난 유효한 신규 결과는 저장하되 최종 결과에 반영하지 마라.

### 제약사항

- 기존 원본과 다른 파트의 코드를 보존하라.
- 기본 seed의 빈 전화번호를 임의의 번호로 대체하지 마라.
- DB 구조와 질문 코드를 변경하지 마라.
- 실발신 차단을 유지하라.
- 대기 기한은 예약 시점부터 600초라는 기존 개발 기준을 유지하라.

### 검증 요구사항

- 로컬 HTTP·MySQL·Redis로 문의 접수부터 음성 워커의 결과 저장·조회까지 검증하라.
- 정상 답변, 일부 미확인, 부재중 후 재시도, 명확한 거절, 응답 유실, 중복 결과와 늦은 결과를 시험하라.
- 해결된 오류, 남은 제약, 백엔드만으로 해결할 수 없는 사항을 구분하여 기록하라.
- 목업 검증 결과를 실통화 검증 완료로 표현하지 마라.

## 결과를 어떻게 썼는지

Codex가 기존 백엔드의 로컬 사본을 수정하고 테스트를 실행했다. 검증된 파일만 작업 브랜치에 반영하며, 기존 음성팀·프론트·공유 설정은 보존했다.

- 워커 선택 옵션과 가짜 결과 생성의 동시 실행 차단 구현
- 거절 응답과 응답 유실 구분, 거절 시 전송 중단·검토 상태 기록
- 결과 수신 시 기한 검사 및 늦은 결과 미반영 구현
- 백엔드 113개·기존 음성팀 26개, 총 139개 테스트 통과
- 실제 로컬 HTTP·MySQL·Redis 시험 9개 통과

## 남은 사항

- 기본 seed의 to=null은 현 음성 워커에서 422로 거절된다. 정상 연결 시험에는 별도 목업 목적지 문자열을 사용했다.
- 거절 원인 해결 후 기존 작업 재개 기능은 추가 개선 과제다.
- 600초는 예약 시점부터 계산하는 개발값이며 운영 기준은 미확정이다.
- 실제 Vapi 발신·분석 지연·AWS 공동 연결은 미검증이다.

상세 실행·검증 내용은 [백엔드 안내](../backend/README.md), [API 기준](../docs/api/README.md), [검증 결과](../docs/verification/backend.md)를 참고한다.
