# 실제 통화 워커에 LLM 판정 연결 (11/9)

- 날짜: 2026-11-09
- 작성자: 김규림
- 사용한 도구: Claude (Claude Code)
- 목적: 10주차 회의 과제인 ClawOps 워커의 LLM 판정 연결. 11/8 backend 답변 계약(`reason='uncertain'`, `source_text`)에 맞춰 보낸다.

## 프롬프트

```
판정 출력 계약에 맞춰 고쳐줘
워커에 LLM 판정 연결하자
llm 실패시 llm 재시도
커밋하고 푸시해서 PR 열어줘
```

## 결과를 어떻게 썼는지

- 배포 이미지에 `voice/call_worker/`만 들어가서, Claude가 판정 모듈을 `voice/judge_eval/`에서 `voice/call_worker/llm_judge.py`로 옮겼다. 평가 스크립트는 옮긴 모듈을 쓴다.
- `LLM_JUDGE_MODEL`이 있을 때만 LLM 판정을 쓰고, 없으면 기존 키워드 판정을 쓴다.
- LLM이 실패했을 때의 정책은 김규림이 정했다. 처음에 Claude가 키워드 판정을 기본값으로 넣고 세 선택지(키워드 판정, 전부 미확인, 섞기)를 제시했다. 김규림은 "LLM을 다시 시도"로 정했다. Claude는 판정 전체를 0·10·30·60초 간격으로 4번 시도하게 했다. 모두 실패하면 키워드로 넘어가지 않고, 모든 질문을 미확인으로 보낸다(키워드 판정은 시험 세트에서 예↔아니오 뒤바뀜 12건).
- 결과 본문은 테스트가 backend `ResultInput` 계약 클래스로 직접 검증한다. 실제 LLM은 부르지 않고, `call_llm`을 바꿔 끼운다.
- 한계: 실제 LLM을 켠 실통화는 아직 하지 않았다. 처리 시간 측정은 다음 작업이다.
