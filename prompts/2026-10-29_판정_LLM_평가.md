# 질문별 판정 LLM 전환 평가

- 날짜: 2026-10-29
- 작성자: 김규림
- 사용한 도구: Claude (Claude Code)
- 목적: 10/28 9주차 회의에서 멘토님이 키워드 사전 판정에 반대해("금토일 안될 것 같습니다" 같은 완곡한 부정 처리 어려움), LLM API 판정으로 바꾸기 전에 같은 시험 세트로 두 방식을 비교한다.

## 프롬프트

```
답변해석 딕셔너리 방식은 멘토님께서 반대하심 다른 방안 탐색(LLM등)
노션에서 10월 28일 회의(9주차회의) 참고
응 1번부터 진행해줘
```

## 결과를 어떻게 썼는지

- Claude가 대안 네 가지(통화 후 LLM 추출, 플랫폼 통화 후 분석, 통화 중 함수 호출 기록, LLM + 근거 검증)를 비교했고, 김규림이 'LLM 추출 + 근거 인용 검증'으로 오프라인 비교부터 하기로 정했다.
- `voice/judge_eval/`을 새로 만들었다. 워커 코드는 바꾸지 않았다. 시험 세트는 10/13 실통화 16통(정답지 `voice/prompts/test_script_v3.md`), 10/19 실통화 2통, 합성 26개다. 합성 사례는 Claude가 키워드 방식이 어려워할 말투를 골라 썼고 정답은 김규림 판정 기준(10/19)으로 붙였다.
- 키워드 방식 기준선: 실통화 56개 중 54개 맞음, 합성 28개 중 20개 맞음(예↔아니오 뒤바뀜 6건).
- 11/1 김규림이 OpenAI 대신 Gemini API 무료 등급을 테스트용으로 쓰기로 했다(역할극·합성 전사만 전송, 실제 학원 통화는 보내지 않음). 무료 등급은 모델당 하루 20건 제한이 있었다(gemini-3.6-flash는 14/44건에서 멈춤). gemini-3.5-flash-lite로 44건을 끝냈다.
- 첫 결과는 LLM 73/84. 틀린 항목을 보니 근거 인용 검사가 너무 엄격했다. 10/13 전사의 빠진 음절을 LLM이 고쳐 옮겨("저 7시터" → "저녁 7시부터") 완전 일치에 실패했다. 글자의 70% 이상이 순서대로 맞으면 인정하게 바꿔 다시 채점했다(API 재호출 없음): LLM 79/84, 키워드 74/84, 예↔아니오 뒤바뀜 1건 대 6건.
- 이 수치의 한계: 70% 기준을 같은 시험 세트를 보고 정했고, 프롬프트 예시 일부가 합성 사례와 겹치며(S05, S07, S09·S10, S11), 합성 사례는 키워드의 약점을 겨냥해 썼다. 처음 보는 사례로 다시 재야 일반 성능을 말할 수 있다.
- 프롬프트 v2(합성 사례와 겹치는 예시 제거, 스키마로 answered 제한)와 시험용 세트 24개(정답을 실행 전 커밋), 10/19 공동 시험 3통을 추가해 gemini-3.5-flash-lite로 다시 쟀다. 전체 121항목 중 LLM 120, 키워드 105. 시험용 세트 25항목 중 LLM 25, 키워드 19. 예↔아니오 뒤바뀜 LLM 0, 키워드 8.
- 한계: 시험용 세트와 프롬프트 v2를 같은 사람(Claude)이 같은 시점에 썼고, 일부 규칙이 시험 사례와 맞닿아 있다(부분 불가 시 미확인 등). 항목 수가 적고 1회 실행이며, 시간 값의 정확성은 채점하지 않았다. 다른 사람이 쓴 사례로 재검증이 필요하다.
- 11/1 김규림 요청으로, 프롬프트와 기존 사례를 보지 못하게 한 별도 에이전트(Sonnet)가 시험 사례 60개(69항목)를 썼다. 정답을 실행 전에 커밋하고 프롬프트 v2를 그대로 돌렸다. LLM 69/69, 키워드 52/69(뒤바뀜 4, 모르는데 확정 9). 정답·메모가 요청에 들어가지 않음을 확인했다.
- 한계: AI가 쓴 말투이고, 정답이 분명한 사례만 쓰게 해서 애매한 말이 빠졌다. 미확인과 거절은 같은 묶음으로 채점했다(거절 1건을 LLM이 미확인과 다르게 판정해도 맞음 처리). 사람이 쓴 사례로 확인이 남았다.
