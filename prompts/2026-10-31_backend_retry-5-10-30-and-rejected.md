# 재시도 간격·횟수 및 수신 거절 재시도 수정

- 날짜: 2026-10-31
- 작성자: 박찬원
- 사용한 도구: OpenAI Codex
- 목적: 기존 백엔드·음성 워커 구조를 유지하며 재시도 간격을 점차 늘리고, 거절 버튼 오조작도 재시도로 처리한다.

## 프롬프트

이번 코드 수정에 직접 사용한 사용자 입력 원문이다. 작업을 구체화한 추가 답변도 순서대로 포함한다.

### 1. 재시도 간격 변경 요청

> 아 오케이 그럼 일단 간단한 작업인 재시도 전화텀 5분 10분 30분 늘리는걸로 가보자

### 2. 총 발신 횟수와 후속 범위 확정

5분·10분·30분 세 간격을 모두 적용할 경우 최초 발신을 포함해 총 4회가 된다는 질문에 다음과 같이 답변했다.

> 총4회 하고 추후 폴백관련기능은 따로정할게

### 3. 거절 버튼도 재시도하도록 추가 요청

> 거절을 누르는것도 사람의 실수로 인해 발생할수있는 사안이니까 자동발신대기열로 넣는게 좋겠어. 해당 사안도 수정진행

### 4. 작업 브랜치·PR 업로드 요청

> 그래 병합까진하지말고 규칙에맞춰서 올려놔

## 결과를 어떻게 썼는지

생성형 AI를 이용해 현재 상태 전이·DB 저장·음성 제공업체 결과 변환 코드를 확인하고, 기존 기능에 필요한 변경과 회귀 시험을 추가했다. 검토 내용 중 아래 항목을 실제 코드에 반영했다.

- 일반 발신은 최초 포함 총 4회로 설정했다.
- 직전 실패 처리 시각부터 5분→10분→30분 뒤 다음 발신을 예약하도록 고정 300초 간격을 변경했다.
- 수신 거절(rejected)을 부재중·통화중·자동응답과 함께 일반 재시도 대상으로 추가했다.
- ClawOps의 거절 버튼/수신자 종료 정보만으로 영구 거절로 단정하던 변환을 unknown으로 수정했다.
- 별도 최종 결과의 명시적인 permanent 거절은 중단하도록 유지하고, 거절 이벤트가 먼저 잡은 예약도 해당 통화가 최신이면 중단하도록 보완했다.
- 중복 이벤트·결과가 재시도 시각을 미루지 않는지, 과거 결과가 새 통화를 취소하지 않는지 시험했다.
- 기존 운영시간·동시성 조건, 명시된 재통화 시각 우선 적용, 지정 실제 통화 시험 총 1회 제한은 유지했다.
- 거절 횟수 소진은 rejected 실패로 기록해 기존 폴백 제외 처리를 유지했다. 새로운 문자·알림톡·링크 폴백 기능은 추가하지 않았다.

## 변경 파일

- backend/service.py: 일반 최대 횟수·차수별 재시도 간격·거절 상태 전이.
- backend/tests/test_retry_schedule.py: 간격 경계·한도·거절 원인·이벤트/결과 순서·중복/과거 결과 시험.
- backend/tests/test_backend.py: 일반 실패 정책과 총 횟수 시험 갱신.
- backend/tests/test_real_test.py: 실제 통화 시험의 거절도 1회 제한을 유지하는지 검증.
- voice/call_worker/real_call.py: 거절 버튼 원인 변환.
- voice/call_worker/test_worker.py: 가짜 제공업체를 사용한 거절 이벤트·결과 변환 시험.
- docs/api/README.md: 변경한 재시도 정책과 적용 범위 안내.

## 현재 반영 상태와 남은 작업

- backend/retry-backoff-5-10-30 작업 브랜치에 코드·검사·문서를 묶어 PR 검토 대상으로 올린다. 사용자 요청에 따라 main 병합과 공동 서버 배포는 진행하지 않는다.
- 이 문서의 검사 수치는 로컬 검증 결과다. GitHub 자동 검사 결과와 최신 반영 커밋은 연결된 PR에서 별도로 확인한다.
- main 직접 푸시 없이 PR을 만들고 해당 최신 변경의 자동 검사를 통과한 뒤 병합하는 협업 규칙을 따른다.
- 실제 통화 시험은 기존 1회 제한으로 유지되므로 일반 재시도 변경으로 실제 재발신이 활성화되지는 않는다.
- 폴백 새 기능은 추후 별도로 결정한다. 다음 발신 시각의 화면 제공·설정 간 일치 검증·중단 이유 구분은 검토 의견이며 이번 코드에 추가 구현하지 않았다.
- 실제 발신·발송, 운영 DB·노션 변경은 수행하지 않았다.
