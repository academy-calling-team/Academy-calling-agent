# 응답 지연 측정

통화 녹음으로 AI 응답 지연(학원 담당자 말이 끝난 뒤 AI 첫 소리까지)을 잰다. 목표는 1.5초 이내다. 10/7 체험 통화 5건의 결과가 `data/results/`에 있다.

|---|---|---|---|---|---|

## 측정 결과 (10/13 같은 설정 비교)

두 엔진 모두 GPT-Live(gpt-live-1, 업무 처리 모델 gpt-5.6-luna, 추론 강도 none, 음성 marin), 프롬프트 v3, 같은 대본으로 휴대폰에 발신했다. 두 엔진 모두 ClawOps 서버 녹음(같은 지점)으로 쟀다. Vapi 통화는 ClawOps 070 → SIP → Vapi(미국)로 이어진다. 대본과 정답지는 `voice/prompts/test_script_v3.md`, 결과 JSON은 `data/results/1013_co_*`(ClawOps), `1013_va_*`(Vapi)다. 엔진마다 대본 A~E 5통과 응답 수를 채우려고 더 건 A·D 2통(`*_A2`, `*_D2`)을 합쳤다.

| 엔진 (대본 A~E + A2·D2, 7통) | 응답 수 | 평균 (초) | 중앙값 (초) | p90 (초) | p95 (초) | 최대 (초) | 1.5초 넘음 |
|---|---|---|---|---|---|---|---|
| ClawOps 070 · GPT-Live | 50 | 1.67 | 1.62 | 1.94 | 1.99 | 2.43 | 40 (80%) |
| Vapi (ClawOps SIP) · GPT-Live | 48 | 1.44 | 1.44 | 1.75 | 1.86 | 2.13 | 20 (42%) |

| 항목 | ClawOps | Vapi |
|---|---|---|
| 정답지 대비 정확도 (요약 기준) | 24/24 | 23/23 (A의 ③은 사람이 대본과 다르게 말해 제외) |
| 첫인사의 AI·녹음 고지 | 8/8 | 8/8 |
| 말 중간 쉼(H)에 끼어듦 | 없음 (1.5~7.3초 쉼 4번) | 없음 (0.9~5.7초 쉼 4번) |
| 끼어들었을 때 AI가 더 말한 시간 (H) | 1.3초, 0.8초 | 1.2초 |
| 되짚기 뒤 답을 기다리지 않음 | B 2번, A2 1번 | B 3번, A2 3번 |
| 말하는 도중 120~300ms 완전 무음 (패킷 빠짐 의심) | 0번 / AI 말 6.2분 | 12번 / AI 말 6.5분 |

- **Vapi의 이른 응답.** Vapi A2·D2에서는 0.6~1.0초 응답이 여러 번 나왔다. Vapi 통화 기록을 보면 GPT-Live가 사람 말이 끝나기 직전에 말을 시작했고, 미국을 오가는 시간이 더해져 국내 녹음 지점에서는 짧은 간격으로 잡혔다. Vapi A2 28.05초의 짧은 "네" 뒤 응답(0.67초)은 AI가 앞 질문에 이어 말하던 중이라 응답에서 뺐다.
- **대본 이탈.** ClawOps D2는 대본 D 대신 A로 답해서 A 정답지로 채점했다. 지연에는 영향이 없다. 처음 건 ClawOps 1통(24초)은 중간에 끊어 뺐다.

- **화자 판정.** 녹음이 두 목소리가 섞인 모노라 `one_call.py`의 목소리 군집만으로는 D·E 등에서 사람과 AI가 갈리지 않았다. 대본의 사람 대사와 AI 말투로 다시 판정하고, 애매한 구간 몇 개는 전사를 보고 직접 정했다(`*_rows.json`의 `who_emb`가 처음 판정, `why`가 근거).
- **H는 지연 통계에서 뺐다.** 일부러 쉬고 끼어든 통화라 따로 본다. 끼어든 시간은 화자 분리 결과로 잰 근삿값이다.
- **목소리.** 통화마다 목소리가 달라진다는 느낌이 있었지만, 화자 임베딩(ERes2Net)으로 비교하면 AI 목소리는 통화끼리 유사도 평균 0.92(0.86~0.97)로, 같은 사람(김규림) 목소리의 통화 간 유사도 0.75보다 높다. 목소리 자체보다 말투·억양이 달라진 것으로 보인다.
- **발음.** 두 엔진 모두 좋지 않다는 평가였다. 같은 GPT-Live 모델의 특성으로 보인다.

## 직접 측정과 비교 (10/14)

10/14에 김규림이 뷰어(`viewer/latency_viewer.html`)에 10/13 녹음 16개를 넣고 화자를 직접 정해 응답 간격을 쟀다. 분석 결과 파일 없이 녹음만 넣어서, 말 구간은 뷰어가 소리 크기로 나눴다. 화면 스크린샷은 `data/human_result/`에 있고, 옮겨 적은 값과 자동 값의 짝은 `data/human_result/human_1013.csv`에 있다.

엔진 비교의 결론은 자동 분석과 같다. 직접 잰 값도 Vapi가 중앙값 0.17초 빠르다.

| 엔진 (대본 A~E + A2·D2) | 측정 | 응답 수 | 평균 (초) | 중앙값 (초) | p95 (초) | 1.5초 넘음 |
|---|---|---|---|---|---|---|
| ClawOps | 직접 | 49 | 1.63 | 1.57 | 1.98 | 33 (67%) |
| ClawOps | 자동 | 50 | 1.67 | 1.62 | 1.99 | 40 (80%) |
| Vapi | 직접 | 48 | 1.40 | 1.40 | 1.78 | 18 (38%) |
| Vapi | 자동 | 48 | 1.44 | 1.44 | 1.86 | 20 (42%) |

- **화자 판정은 거의 같다.** 16통 중 14통에서 응답 개수와 순서가 자동 분석과 같았다. 다른 두 통은 아래 '확인할 것'에 있다.
- **직접 잰 값이 평균 0.04초 짧다.** 짝이 맞는 84쌍(H 제외)에서 직접−자동은 평균 −0.04초, 중앙값 −0.03초다. 66쌍은 차이가 0.05초 이내다. 원인은 사람이 아니라 말소리로 보는 소리 크기 기준이다. 뷰어는 −60dB 이상을, 자동 분석은 −50dBFS 이상을 말로 본다. 그래서 뷰어는 말 끝의 숨소리나 잔향까지 말로 잡아 간격이 짧아진다. 0.1초 넘게 차이 난 6곳과 차이가 작은 1곳을 뷰어와 같은 방식으로 다시 계산했더니, −60dB 기준 값은 직접 잰 값과 7곳 모두 같았고 −50dB 기준 값은 자동 값과 6곳이 같았다(다른 1곳은 아래 Vapi A2).
- **1.5초 넘음은 기준에 민감하다.** 응답이 1.5초 근처에 몰려 있어서 0.04초 차이로 ClawOps의 1.5초 넘음 비율이 80%에서 67%로 바뀐다. 앞으로는 소리 크기 기준을 −50dBFS로 통일해 잰다.
- **중앙값 표시.** 10/14 뷰어는 응답 수가 짝수일 때 가운데 두 값 중 작은 값을 중앙값으로 보여 줬다. 위 표는 다시 계산한 값이다.

**확인할 것 (뷰어에서 들어 보기)**

- [ ] ClawOps D 59.98~60.18초. 자동 분석은 사람 말이 59.60초에 끝났다고 봤고(전사 "네, 화요일 오 5시에 오"), 이 0.2초 조각이 사람 말 끝("세요")이면 응답 간격은 1.70초가 아니라 약 1.11초다. 직접 측정에서는 이 조각이 미정으로 남아 응답이 빠졌다.
- [x] ClawOps D 40.9초 부근 응답은 표시선으로 1.83초를 찍고 '측정 추가'를 누르지 않았다. 위 표의 직접 값에는 넣었다(자동 1.87초).
- [x] Vapi E 63.11초의 0.34초는 응답이 아니다. AI 요약의 첫 음절(62.85~63.11초)이 사람으로 칠해졌다. 위 표에서 뺐다.
- [ ] Vapi A2 첫 응답은 자동 값(0.60초)이 오히려 짧다. 사람 말은 2.60초에 끝나고 2.85초 부근의 짧은 소리까지 사람 말로 붙은 것으로 보인다. −50dB 경계로는 0.88초다.

## 재측정 (11/2)

10/13과 같은 시험 에이전트로 대본 A~E·H를 엔진마다 한 번씩, 총 12통 걸었다(`scripts/call_log.py`, `data/calls_1102.csv`). 김규림이 서버 녹음과 휴대폰 녹음을 뷰어(−60dB)로 직접 쟀다(`data/human_result/human_1102.csv`, `human_1102_phone.csv`). 표는 대본 A~E 값이다.

| 측정 지점 | 엔진 | 응답 수 | 평균 (초) | 중앙값 (초) | p95 (초) | 최대 (초) | 1.5초 넘음 |
|---|---|---|---|---|---|---|---|
| 서버 | ClawOps | 36 | 1.76 | 1.73 | 2.17 | 2.40 | 29 (81%) |
| 서버 | Vapi | 35 | 1.81 | 1.73 | 2.52 | 2.95 | 27 (77%) |
| 휴대폰 | ClawOps | 33 | 2.08 | 2.03 | 2.52 | 2.77 | 33 (100%) |
| 휴대폰 | Vapi | 35 | 2.23 | 2.16 | 2.96 | 3.10 | 35 (100%) |

- **10/13과 다른 점.** 서버 중앙값이 10/13 직접 측정(ClawOps 1.57초, Vapi 1.42초)보다 각각 0.16초, 0.31초 길어져 Vapi의 우위가 재현되지 않았다. 설정은 같고 원인은 확인하지 못했다. 통화를 다시 뽑은 부트스트랩의 Vapi−ClawOps 중앙값 차이 95% 구간은 −0.20~+0.31초다.
- **휴대폰망 구간.** 같은 응답의 휴대폰−서버 차이 중앙값은 ClawOps 0.35초, Vapi 0.44초다.
- **끊김.** 자동 분석(12통, AI 발화)에서 120~300ms 무음은 ClawOps 3번, Vapi 2번이고, 무음 조각 전체는 27개, 8개다. 10/13의 0번, 12번과 다르다.
- **정확도와 행동.** 전사와 정답지를 대조하면 요약 정확도는 두 엔진 모두 18/18, AI·녹음 고지는 6/6이고, 대본 H의 쉼에 끼어들지 않았다.
- **전사 도달.** 통화 후 ClawOps에 전사를 요청하면 중앙값 10.0초, 범위 2.2~57.8초에 끝났다(`data/results/1102_*_clawops_transcript.json`). Vapi 통화도 ClawOps 쪽 통화 기록으로 받을 수 있다.
- **뺀 값.** 휴대폰 `1102_co_D`의 0.35초, 1.58초, 1.62초는 같은 자리의 서버 값과 맞지 않아 뺐다(`human_1102_phone.csv`의 `use`=0).
- **표본.** 한 사람이 하루 저녁 건 대본 통화이고 프롬프트 v3 값이다. 서비스 프롬프트의 지연은 재지 않았다.

## 프롬프트 길이·말하는 모델 시험 (11/11)

10주차 회의(11/4) 과제였던 '프롬프트를 줄이거나 모델을 바꾸면 지연이 줄어드는가'를 ClawOps에서 시험했다. 세 에이전트를 만들고, 대본 A~E·H마다 한 번씩 같은 밤에 섞어서 18통을 걸었다(`scripts/variants_1111.py`, `data/calls_1111.csv`).

| 묶음 | 바꾼 것 | 설정 |
|---|---|---|
| L 기준 | 없음 | 지금 시험 에이전트. 프롬프트 v3(2,451바이트), live · gpt-live-1 + gpt-5.6-luna · 추론 none · marin |
| S 짧게 | 프롬프트만 | `voice/prompts/agent_prompt_v3_short.txt`(1,087바이트, v3의 44%). 점수 매기는 행동 규칙은 남기고 설명과 예외 처리를 줄임 |
| M 모델 | 말하는 모델만 | realtime_voice · gpt-realtime-2.1-mini · marin. vad·session은 넣지 않아 ClawOps 기본값 |

- **순서.** 대본마다 세 묶음의 순서를 바꿔 각 묶음이 첫째·둘째·셋째에 두 번씩 오게 했다. 실제 순서는 무작위로 정해 `data/calls_1111_order.json`에만 뒀다.
- **가린 측정.** 김규림이 묶음을 모른 채 휴대폰 녹음을 뷰어(−60dB)로 직접 쟀다. 통화 화면과 측정용 녹음에는 무작위 측정 번호(01~18)만 보였고, 대응표(`data/calls_1111_key.csv`)는 측정이 끝난 뒤 열었다. 통화 중 메모도 번호로만 남겼다(`data/calls_1111_notes.txt`).
- **자료.** `data/human_result/human_1111_phone.csv`(응답 126개, 대본 B 1통은 다시 걸어 버림). 통계는 `scripts/human_stats_1111.py`.

휴대폰 직접 측정, 대본 A~E(묶음마다 5통):

| 묶음 | 응답 수 | 평균 (초) | 중앙값 (초) | p95 (초) | 최대 (초) | L 대비 중앙값 차이 (통화 단위 95% 구간) |
|---|---|---|---|---|---|---|

| S 짧은 프롬프트 | 34 | 2.17 | 2.16 | 2.81 | 2.90 | +0.04 (−0.09~+0.15), 통화별 중앙값 Mann-Whitney p=0.25 |

- **프롬프트 길이.** 절반 넘게 줄여도 중앙값 차이는 구간 기준 ±0.15초 안이었다. 0.1초를 넘게 빨라지지는 않는다.
- **모델.** mini는 5통 모두 L보다 느렸다(통화별 중앙값 2.57~3.21초, L은 1.98~2.19초). "잠시만요"로 먼저 말을 시작한 통화도 있어, 실제 답까지는 더 걸렸다.
- **기준선.** L 중앙값 2.12초는 11/2 같은 에이전트의 휴대폰 측정(2.03초)과 비슷했다.

- "네, 들어가세요" 뒤 AI가 스스로 끊었다는 메모는 S 1통, M 1통이고 위 표에는 넣지 않았다. S 1통은 끝내겠다고 말하고 끊지 않았다. 대본 B의 버린 통화에 적은 메모 1줄은 세지 않았다.

- **결론.** 프롬프트를 줄여도 빨라지지 않았고 되짚기를 덜 지켰다. mini는 느리고 정확도와 말투도 나빠졌다. 지금 구성(gpt-live-1, 지금 길이의 프롬프트)을 유지한다.
- **M 설정 주의.** vad·session을 비워 둔 기본값이 ClawOps 음성 감지를 켜는 구성이라면 그만큼 지연이 붙었을 수 있다. 모델만의 차이로 단정하지 않는다.
- **앞부분 보충.** 09번(E·L)과 10번(B·M) 통화는 학원 첫인사와 AI 첫인사 사이에 0.1~0.2초 짧은 소리가 있어 뷰어가 첫 간격을 잡지 못했다. 14번과 같은 기준으로 직접 다시 쟀다.
- **한계.** 한 사람이 한 저녁에 건 대본 통화 15통(+H 3통)이다. M은 목소리로 짐작할 수 있어 완전히 가린 측정은 아니다. 행동 표는 통화 중 메모 기준이라 전사 대조로 확인하지 않았다.

## 측정 방법

- 응답 지연 = AI 첫 소리 시작 − 사람 말 끝. 사람 → AI로 바뀌는 지점마다 잰다.
- silero VAD로 음성 구간을 찾고, 에너지로 경계를 10ms 단위로 맞춘다. ClawOps 녹음은 말 사이가 디지털 0이라 경계가 뚜렷하다.
- 화자는 ERes2Net 임베딩으로 가르고, Whisper turbo 전사로 확인한다.
- 간격이 0초 이하인 겹침(맞장구 '네', 끼어들기)은 응답에서 빼고 따로 출력한다. p95는 nearest-rank다.

## 준비

1. Python 3.10 이상과 ffmpeg(새 녹음을 변환할 때만)를 준비한다.
2. `pip install -r requirements.txt`
3. `python scripts/download_models.py`로 모델을 받는다. 약 610MB를 받아 1.1GB로 풀고, 10/7 측정에 쓴 파일과 SHA-256으로 대조한다. 기본 위치는 `models/`(커밋하지 않음)이고, 다른 곳에 두려면 환경 변수 `MODELS_DIR`을 지정한다.
4. 녹음을 `data/recordings/<날짜>/`에 넣는다(예: `data/recordings/1102/1102_co_A.wav`, 날짜 없는 10/7 녹음은 `1007/`). 스크립트는 `scripts/paths.py`의 `rec_file`로 이름 앞 네 자리를 보고 폴더를 찾는다. 녹음은 저장소에 올리지 않는다(`.gitignore`). 10/7 녹음은 김규림 Google Drive에 있으니 필요하면 요청한다.

## 파형 보며 직접 재기 (뷰어)

`viewer/latency_viewer.html`을 브라우저로 연다. 설치는 필요 없다. 녹음 파일(WAV·m4a·mp3)과 분석 결과(`data/results/<이름>_rows.json`)를 함께 끌어다 놓으면 파형이 화자 색(사람·AI)으로 칠해지고, 자동으로 잰 응답 간격이 띠로 표시된다. 결과 파일 없이 녹음만 넣으면 소리 크기로 말 구간만 나누므로, 구간을 누르고 `1`(사람)·`2`(AI)로 정한다.

- 표의 응답을 누르면 그 지점으로 확대되고 앞 1초부터 재생 위치가 잡힌다. 0.5배속으로 들으며 확인한다.
- 자동 값이 틀렸으면 표시선(사람 말 끝·AI 시작)을 끌어 옮기고 '선택한 응답을 이 값으로 고치기'를 누른다. 새로 재려면 `[`·`]`로 표시선을 찍고 `Enter`.
- 요약(응답 수, 평균, 중앙값, p95, 1.5초 넘음)은 표에서 '빼기'하지 않은 응답으로 계산한다. 'CSV 복사'로 결과를 가져간다.
- 녹음은 브라우저 안에서만 읽고 어디에도 올리지 않는다. 고친 값은 그 브라우저에만 저장된다.
- **말소리 기준.** 결과 파일 없이 나눌 때 이 크기보다 큰 소리를 말로 본다. 기본 −50dB는 자동 분석의 경계 기준(−50dBFS)과 같다. −60dB는 말 끝 숨소리까지 말로 잡아 간격이 짧아진다(10/14 직접 측정은 이 기준이었다). 기준을 바꾸면 사람·AI 표시는 겹치는 구간을 따라 옮겨진다.

## 한 번에 돌리기 (`measure.py`)

10/13 측정에 쓴 과정(녹음 받기 → 변환 → 화자 분리·전사 → 화자 재판정 → 응답 간격 → 보고)을 통화 목록 CSV 한 장으로 돌린다. 10/13 통화 목록은 `data/calls_1013.csv`다. 열의 뜻은 `scripts/measure.py` 맨 위 설명에 있다.

```
python scripts/measure.py fetch   data/calls_1013.csv      # ClawOps 서버 녹음 받기 (Vapi 통화는 ClawOps 쪽 통화를 시각으로 찾음)
python scripts/measure.py analyze data/calls_1013.csv      # 통화마다 분석, '?'로 남은 구간을 보여 줌
python scripts/measure.py fix     data/calls_1013.csv      # CSV의 fix 열(직접 정한 화자)만 다시 적용
python scripts/measure.py report  data/calls_1013.csv      # 엔진별 지연·겹침·목소리·끊김
python scripts/measure.py transcript data/calls_1013.csv 1013_va_C   # 정답지 대조용 전사
```

- sherpa-onnx가 깔린 가상환경 파이썬으로 실행하고, 키는 저장소의 `voice/.env`에서 읽는다.
- 화자 판정은 대본(`voice/prompts/test_script_v3.md`)의 사람 대사와 AI 말투로 한다(`scripts/relabel.py`). 새 대본을 쓰면 `relabel.py`의 `SCRIPT`에 사람 대사를 넣는다.
- `one_call.py`는 10/7 통화 1의 사람 목소리를 기준으로 쓰므로 `call1.json`과 `call1_16k.wav`가 있어야 한다.
- **재현 확인 (10/14).** `data/calls_1013.csv`로 `fix`·`report`를 돌리면 저장된 결과와 같은 값이 나온다(ClawOps 50개 중앙값 1.62초, Vapi 48개 중앙값 1.44초). `analyze`로 통화 하나를 처음부터 다시 돌려도 결과 JSON이 같았다.

## 분석 다시 돌리기 (스크립트 하나씩)

명령은 모두 이 폴더(`experiments/latency/`)에서 실행한다. 결과는 `data/results/`에 쓴다.

**ClawOps 통화 1·2 (측정 표의 18개 응답)**

```
python scripts/turns.py data/recordings/1007/call1_16k.wav call1

**새 ClawOps 통화 한 건** (예: `call3.wav`를 `data/recordings/1007/`에 넣은 뒤. 날짜 없는 이름은 1007 폴더에서 찾는다)

python scripts/one_call.py data/recordings/1007/call3_16k.wav call3

```
