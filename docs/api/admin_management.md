# API 문서 화면에서 학원·문의 관리

운영 관리자만 전체 학원 조회·부분 수정·학원 삭제·학부모 문의 조회/삭제를 수행한다. 학원 계정의 `account_type=academy`는 운영 관리자 `role=admin`과 다르다. 회원가입은 항상 member로 등록하며 요청으로 admin을 선택할 수 없다.

## 로그인과 사용 순서

1. 배포된 `/shared/docs`를 연다. PR 단계에서는 공개 서버에 아직 새 기능이 없다.
2. `POST /auth/login`에 기존 관리자 아이디·비밀번호를 입력한다.
3. 반환된 `access_token`을 상단 **Authorize**의 Bearer 인증에 입력한다. 인증값을 공용 문서·팀 채팅·스크린샷에 넣지 않는다.
4. **관리자 · 학원·문의 관리**에서 **Try it out → Execute**를 사용한다.
5. 사용 후 `POST /auth/logout`으로 세션을 폐기하고 Authorize 값을 비운다.

문서 주소를 안다고 권한이 생기지 않는다. 모든 새 경로에서 서버가 유효 세션과 현재 admin 권한을 확인한다. 미인증/만료/로그아웃/비활성 계정은401, 일반 학부모·학원 계정은403이다. 관리자 계정 생성은 서버 전용 도구로만 수행한다.

## 학원 조회·수정

| 요청 | 용도 |
|---|---|
| `GET /ops/academies?q=&limit=50&offset=0` | 학원명·전화번호 검색, 현재 정보/버전 조회 |
| `GET /ops/academies/{academy_id}` | 특정 학원 현재 값 조회 |
| `PATCH /ops/academies/{academy_id}` | 지정한 항목만 수정 |

조회 응답의 `version`과 수정할 항목만 전송한다. 설정 기록이 없는 기존 학원은 version0부터 시작한다. 예시 번호는 실제 수신 번호가 아니다.

```json
{"version": 0, "name": "회의 시연 학원", "phone": "010-0000-0001"}
```

수정 가능 항목은 `name`, `phone`, `region`, `address`, `classes`, `call_hours`다. 주소는 소유자가 등록된 학원에서만 수정한다. 생략한 값은 보존한다. `classes=[]`는 운영 반을 비우며, call_hours는 최소1개·정상 시간·겹침 없음이 필요하다. 기존 기본 hours와 새 응대 시간 목록의 의미는 바꾸지 않는다.

목업 여부·학원 ID/소유자·회원 권한·발신 허용 설정은 수정할 수 없다. 진행 중인 통화가 있으면409. 다른 관리자/학원 소유자가 먼저 수정했다면409이므로 다시 조회한다. 기존 학원 소유자 수정 API와 운영 반·응대 시간 전용 API도 유지한다.

## 문의 조회·삭제

`GET /ops/inquiries`의 `academy_id`, `inquirer_id`, `status`, `limit`, `offset`으로 범위를 좁힌다. 문의 ID·학원·학부모 로그인명·상태를 확인한다. 학부모 본인의 기존 조회 권한은 유지한다.

1. `GET /ops/inquiries/{id}/delete-preview`로 삭제 건수·차단 사유·preview_token을 확인한다.
2. can_delete=true일 때 `DELETE /ops/inquiries/{id}`에 정확한 ID와 미리보기 값을 입력한다.

```json
{"confirm_id": "삭제할 문의의 실제 ID", "preview_token": "미리보기에서 받은 64자리 값"}
```

한 번에 문의1개와 해당 DB의 질문·통화·답변·결과·교정·이벤트·검토·발신 대기/전달 기록을 외래키 순서대로 삭제한다. 회원 계정과 다른 문의는 유지한다. 진행 중 통화/전달 또는 녹음 참조가 있으면 삭제하지 않는다. 외부 음성 서비스·워커 보관 기록·녹음 파일을 지우는 API는 아니다.

미리보기 후 대상이 변경되면409, 확인 ID 불일치는422, 이미 없는 대상은404다. DB 권한 오류면503이며 전체 삭제를 롤백한다. 지연된 Redis 메시지·워커 반환이 삭제한 문의를 되살리거나 큐를 멈추지 않도록 처리한다.

## 학원 삭제

`GET /ops/academies/{id}/delete-preview` 후 `DELETE /ops/academies/{id}`에 같은 확인 본문을 쓴다. 연결 문의가 남아 있으면 먼저 문의를 개별 삭제한다. 학원1개와 운영 반·응대 시간·정책·설정 버전·소유자 연결만 삭제하며 학원 회원 계정은 유지한다. 소유자는 이후 다시 학원을 등록할 수 있다.

성공한 수정·삭제는 서버 로그에 작업자 ID·대상 ID·항목/건수로 남긴다. 전화번호·학생 정보·전사·인증값은 작업 로그에 쓰지 않는다. 별도 영구 감사 테이블은 추가하지 않는다.

## 서버 반영 전 준비

DB 구조 변경은 없다. 현재 앱 계정은 일부 테이블의 DELETE 권한이 없으므로 코드 배포만으로 삭제 기능이 준비되지는 않는다.

기존 EC2 운영자 터미널에서 검토한 `infra/admin-management-permissions.py`를 실행한다. 기본은 누락 권한 확인, `--apply`를 붙이면 대상21개 테이블에만 DELETE를 추가한다. DB 전체 권한·계정/세션 삭제 권한·root 권한은 앱에 부여하지 않는다. 이 준비 도구 자체는 DB 행을 삭제하지 않는다.

관리자 계정이 없다면 운영자가 약관에 실제 동의한 뒤 API 컨테이너의 `python manage_admin6.py <새관리자아이디> --terms-agreed`를 대화형 터미널에서 사용한다. 비밀번호는 숨김 입력이다. API로 회원 권한을 승격하는 경로는 추가하지 않는다.

실제 발신 활성화나 신규 학원의 발신 제한 해제는 별도 후속이다. 공유 DB에서 삭제할 기존 학원/문의는 사용자가 지정하며 구현 검증에서 임의로 지우지 않는다.
