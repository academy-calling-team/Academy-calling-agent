# 음성 엔진 운영 기준

2026-11-12 사용자 확인: 팀이 최종 선택한 음성 엔진은 **ClawOps**다. 이전 비교 문서의 Vapi 전환 조건은 당시 검토 기록이며 현재 운영 선택지가 아니다.

## 현재 실행 경로

- 화면 → 백엔드 문의·발신 큐 → `voice/call_worker/worker.py` → ClawOps → 공통 이벤트·결과 API → 저장·결과 화면.
- `voice/call_worker/clawops.py`는 실제 ClawOps 통신, `real_call.py`는 통화 ID 보존·이벤트·결과 전송을 담당한다.
- 서비스 에이전트 준비는 `voice/engines/setup_service_agent.py`, 공통 설정은 `voice/engines/clawops_agents.py`를 사용한다. 기존 모델·음성·프롬프트와 요청 본문은 유지한다.
- 전사 후처리는 `LLM_JUDGE_MODEL` 설정에 따라 LLM 또는 기존 키워드 판정을 사용한다. 음성 엔진 결정과 후처리 모델 설정은 구분한다.
- `voice/mock_worker`는 실제 전화 없이 접수·이벤트·결과 계약을 시험하는 목업으로 유지한다.

## 설정과 시험

음성 담당은 `voice/.env.example`을 참고한다. 기존 개인 `.env`는 덮어쓰지 않는다. 실제 발신 기본값은 OFF이며 ClawOps 값 4개와 허용 번호·백엔드 지정 계정·양쪽 활성화 조건을 맞춘 뒤 별도 시험한다. 지정 실통화 시험의 문의당 1회 제한은 유지한다.

팀원 화면 설치는 [공동 개발 안내](collaboration/README.md), 실제 통화 설정은 [실통화 워커 안내](../voice/call_worker/README.md)를 따른다. 엔진 결정만으로 원격 자원 삭제·결제 해지·서비스 에이전트 갱신·실제 발신을 실행하지 않는다.

## 정리 범위와 과거 자료

- 사용하지 않는 백엔드 `provider6.py` 변환 예제와 전용 시험, Vapi 트렁크 등록 도구, 두 플랫폼 동시 에이전트 생성 도구를 현재 코드에서 제거했다.
- 기존 DB의 제공업체 매핑·수신함 테이블은 이력 및 스키마 호환용으로 보존한다. 현재 ClawOps 워커의 통화 ID·재전송 상태는 워커 SQLite와 공통 백엔드 이벤트·결과 경로에서 관리한다.
- 비교 측정 데이터, 분석 스크립트, 회의록·논문·과거 AI 사용 기록은 당시 판단의 근거로 보존한다. 과거 도구는 [정리 전 커밋](https://github.com/academy-calling-team/Academy-calling-agent/tree/dce78f0203a5b9b42c2273f994f3828ac5a78c41/voice/engines)에서 확인할 수 있다.
