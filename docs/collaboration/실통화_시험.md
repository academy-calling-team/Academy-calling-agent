# 프론트·백엔드·음성 실통화 시험

2026-10-19. PR #25 음성 계약을 유지한 통합 기능이다. 일반 학원은 목업이며 `team8-real-call-test` 학원만 실제 발신 대상으로 사용한다. 시험 학원도 서버 활성화·지정 로그인 계정·허용 수신 번호가 모두 맞아야 한다. 한 문의의 발신 시도는 최대 1회이며 미응답·통화 중·자동응답·재통화 요청에도 자동 재발신하지 않는다. 같은 문의의 전달 재시도는 같은 call_id를 유지한다. 새 문의를 접수하면 새로운 전화 요청이므로 반복 접수하지 않는다.

## 현재 준비 상태와 입력 위치

ClawOps 설정은 음성팀 PC에만 있다. 프로그램 배포만으로 실제 발신이 켜지지 않는다. 음성팀의 새 서비스 에이전트·잔액·발신 번호와 수신자 준비를 확인한 뒤 운영자가 아래 절차로 설정한다. 키·전화번호를 Git, 채팅, 프론트 설정 또는 명령줄 인수에 넣지 않는다.

프론트에서 약관에 동의해 시험용 일반 계정으로 가입한 뒤 로그인한다. 기존 동의 계정도 가능하다. 관리자 계정은 필요 없다. 운영자에게 이 계정의 로그인 아이디만 알려준다.

AWS 콘솔 → EC2 → 해당 인스턴스 → 연결 → Session Manager의 **대화형 터미널**에서 실행한다. 개인 SSH 연결을 사용해도 된다. 아래 설정은 입력 내용이 보이지 않는 프롬프트로 받는다. 자동 실행용 SSM Run Command에 비밀값을 넣지 않는다.

```bash
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py status
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py configure
```

configure가 차례대로 묻는 값:

| 입력 | 준비 담당·내용 |
|---|---|
| Existing frontend test login name | 백엔드·프론트, 약관에 동의한 기존 시험 계정 |
| Receiver mobile number | 시험 직전에 정한 수신자 개인 휴대폰, +8210… 또는 010… |
| CLAWOPS_API_KEY | 음성팀 PC의 ClawOps API 키 |
| CLAWOPS_ACCOUNT_ID | 음성팀 계정 ID |
| CLAWOPS_SERVICE_AGENT_ID | 이번 서비스용 에이전트 ID. 과거 CLAWOPS_AGENT_ID와 구분 |
| CLAWOPS_FROM_NUMBER | 음성팀이 시험한 발신 번호 |

configure는 학원 phone·양쪽 허용 번호·지정 계정을 맞추고 컨테이너 3개를 재생성하지만 **실발신은 꺼 둔다**. 기존 MySQL·Redis·접수 SQLite 볼륨과 다른 서비스는 유지한다. 설정 파일은 서버 root 전용이다. 활성 통화·대기 문의가 있으면 변경을 보류한다. status는 준비 여부만 출력하며 키·번호를 출력하지 않는다.

## 시험 시작

1. 음성팀이 PR #25 기반 새 워커의 로컬 실통화 결과를 확인하고, 수신 담당자가 지금 받을 준비를 한다.
2. 운영자가 아래 enable을 실행하고 수신자 준비 확인에 `ENABLE`을 입력한다. API·큐·워커를 재생성해 환경설정을 반영한다. 같은 SHA의 Actions 재실행이나 docker restart만으로 바꾸지 않는다.

```bash
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py enable
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py status
```

3. 각 PC에서 최신 main을 받고 프론트를 재시작한다. 공식 작업 폴더에서는 `프론트_실행.cmd`를 실행하고 http://127.0.0.1:3000 으로 접속한다. 이미 열려 있던 화면은 새로고침한다.
4. configure에 지정한 계정으로 로그인 → 새 상담 → **실통화 시험용 학원** 선택. ‘시험 준비 중’이면 활성화가 안 된 것이므로 접수하지 않는다. 일반 학원 선택은 기존 목업 시험이다.
5. 학생 M2 / MATH / MID / 대구 북구 침산동, 질문 **통학 차량(shuttle)·픽업(pickup)·수업 시간(class_time)** 선택. 문의 정보 사용 동의와 실제 전화·수신자 준비 확인을 직접 체크한다. 상담 접수를 한 번 누른다.
6. 상태 화면을 열어 두고 전화에 응답한다. 예상 3~5분은 음성팀 추정이며 실측 전이다. 예약 후 결과 대기 기준은 600초다. 시간이 지나면 먼저 문의·전화 상태를 확인하고 새 문의로 무작정 재접수하지 않는다.

## 수신자 대본과 결과 확인

| 질문 | 수신자 답변 | 화면 기대값 |
|---|---|---|
| 통학 차량 | 네, 침산동 쪽으로 다녀요 | 가능, answered=true·yes_no=true |
| 픽업 | 픽업은 안 해요 | 불가, answered=true·yes_no=false |
| 수업 시간 | 화목 저녁 7시요 | 시간 확인, yes_no=null·원문 표시 |
| 상담 | 수요일 3시에 오세요 | 수락·시간 원문 대조, 아래 알려진 한계 참조 |

실패 없이 통화하고도 답이 애매하면 ‘미확인’과 원문이 표시될 수 있다. ‘불가’와 ‘미확인’을 구분한다. 연락 기록은 1차까지만 있어야 한다. 완료는 상담 예약 확정이 아니다.

**이번에 보류한 항목:** 음성팀의 상담 시간 추출은 첫인사 ‘AI 상담원’에 걸려 ‘네 말씀하세요’를 시간으로 잡는 재현이 있다. 사용자 요청으로 이 보완은 이번 범위에서 건너뛰었다. 상담 수락·가능 시간의 정확성은 실제 답변과 별도로 대조해야 하며 세 질문의 통합 시험 성공만으로 상담 추출까지 완료로 기록하지 않는다.

## 시험 종료와 문제 대응

통화와 결과 수신을 확인한 후 운영자가 실행한다.

```bash
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py disable
sudo python3 /opt/team8-shared-api/deploy/real-call-test.py status
```

disable은 양쪽 발신 활성화·허용 번호·지정 계정을 제거하고 학원 phone을 비운 뒤 컨테이너를 재생성한다. 다음 시험은 configure부터 시작한다. 기존 결과는 보존하고 일반 학원 목업 1건을 접수해 정상 완료를 확인한다. ClawOps 키는 root 전용 worker.env에 남으므로 폐기가 필요하면 음성팀과 운영자가 비공개로 처리한다.

- 409 시험 안내: 서버 준비 또는 지정 계정 불일치. 운영자 status와 로그인 아이디를 확인한다.
- 워커 거부·결과 시간 초과: 실발신이 시작됐는지 먼저 확인한다. 같은 수신자에게 새 문의로 재발신하지 말고 backend call_id와 워커 영속 접수를 대조한다.
- 설정 재생성 실패: 도구는 실발신을 비활성화하고 공동 컨테이너를 정지한다. root 터미널에서 오류를 확인해 복구한다. 비밀 설정이 든 docker inspect·env 내용을 팀 채팅에 붙이지 않는다.
- 진행 중 시험에서 긴급히 추가 작업을 막아야 하면 프론트 접수를 중지하고 운영자가 먼저 `sudo docker stop team8-shared-queue`를 실행한다. 이미 시작한 전화의 취소는 ClawOps에서 음성팀이 확인한다. 종료 후 disable을 진행한다.

## 검증 범위

로컬 전체 자동 테스트: 백엔드 132개(실제 로컬 MySQL·Redis), 음성 목업 30개·실통화 워커 29개(가짜 제공업체, 워커 접수 SQLite). 실제 MySQL·Redis 큐→허용 어댑터→실통화 워커→가짜 ClawOps→이벤트·결과 저장·본인 조회에서 3개 답의 true/false/시간 구분을 추가 확인했다. 외부 ClawOps 실발신은 이 검증에 포함되지 않는다.

자동 배포 검사는 이번 변경부터 별도의 일회용 MySQL·Redis로 백엔드 전체 테스트, 음성 두 워커 테스트, 프론트 타입·약관 계약·빌드를 실행한다. 운영 DB의 전체 데이터를 테스트하거나 실제 전화를 거는 검사는 아니다. 프론트는 PC 실행이며 자동 배포 대상은 공동 API·큐·워커다.
