# 음성 결과 PR58·PR61 병합과 DB 적용 순서

PR58은 수신 계약·검증·호환 기반, PR61은 그 코드를 포함한 저장·근거 조회·권한·교정 후속이다. 두 PR의 작성자 커밋과 이력을 보존하며, 적용 시 아래 순서를 따른다. 이 문서는 병합/서버 변경을 실행한 기록이 아니다.

## 준비된 PR 관계

1. PR58 브랜치에 최신 main을 merge commit으로 통합해 회귀 검사를 갱신한다.
2. PR61 브랜치에 그 PR58 브랜치를 통합하고 보완 커밋을 추가한다. 동일한 선행 변경을 다시 작성하거나 cherry-pick하지 않는다.
3. 두 PR의 **최신 head** 검사가 통과했는지 확인한다. 이전 커밋의 성공만으로 대체하지 않는다.
4. 병합 시에도 merge commit 방식을 권장한다. PR58을 squash/rebase하면 PR61에 포함된 선행 커밋과 이력 대응이 달라질 수 있으므로, 방식을 바꿔야 한다면 PR61 차이를 다시 확인한다.

## 승인된 공동 적용 때 진행할 순서

1. **PR58을 먼저 병합**한다. main의 검사·API/워커/큐 자동 배포 성공과 실제 실행 버전을 확인하고, 기존 목업 접수·조회가 유지되는지 확인한다. PR58 자체에는 DB 컬럼 추가가 없다.
2. **공동 DB의 실제 컬럼 상태를 읽어 확인하고 변경 전 백업을 확보**한다. PR61 SQL은 `w5_answers.condition VARCHAR(200) NULL`, `reason_text VARCHAR(500) NULL`, `evidence_turns JSON NULL`을 추가한다. 이미 적용된 컬럼은 존재·타입을 확인하고 임의로 지우지 않는다.
3. 선택한 커밋의 `docs/database/migrations/20261117_voice_result_answers.sql`을 대상 DB에 적용한다. 기존 행/답변 보존·3개 nullable 컬럼을 확인한다. SQL은 반복 및 부분 적용을 견디도록 작성되어 있으며 일회용 MySQL 회귀 시험으로 확인한다.
4. **PR61을 최신 main과 다시 대조**한다. 추가 변경이 있으면 통합 후 최신 head CI를 재확인하고 병합한다. PR61 main 검사·배포·실행 API/워커/큐 버전·DB 구조와 지정 목업 왕복을 확인한다.
5. 그 뒤 프론트와 음성 워커를 연동한다. 새 워커 필드는 수신/저장/조회와 화면이 준비된 후 전송한다. 기존 라벨/근거 기준을 바꾸는 작업으로 확대하지 않는다.

**자동 배포는 새 DDL을 실행하지 않는다.** 현재 배포 사전 검사는 새 코드가 요구하는 컬럼이 실제 DB에 있는지 확인한다. 3개 컬럼이 빠진 상태로 PR61을 먼저 배포하면 schema 단계에서 실패할 수 있다. 자동 배포의 백업도 수동 DDL 이전 백업을 대신하지 않는다.

이번 SQL은 nullable 컬럼 추가이므로 이전 코드가 원래 컬럼을 읽고 쓰는 방식과 호환된다. 이미 SQL이 적용된 환경에서는 PR58 단계에서도 기존 컬럼이 유지되는지 확인한다. 별도 스키마 대조에서 나타나는 추가 컬럼은 이 과도기 변경과 구분한다.

## 보완한 오류 위험

- 시간 초과·늦은 결과를 최종 문의에 반영하지 않는 것은 유지한다. 하지만 권한 있는 운영자/학원 소유자가 저장된 전사를 진단할 수 있어야 하므로 전사 조회에서만 applied 필터를 제거하고 응답에 applied 값을 추가했다.
- 시각 미정 재연락을 완료로 표시하면 후속 확인이 누락될 수 있다. 목업의 실제 동작인 retry_wait/review_required=true/callback_time_unknown을 문서와 API 회귀 시험에 함께 반영했다.
- 프론트 응답 예시의 중복 경로를 정리하고 선행 문서의 'DDL 없음'을 PR58 단계로 명시했다.

## 이번 작업에서 하지 않는 것

- main 병합·자동병합 설정·공동 DB 쓰기·서버 배포·실제 전화/외부 LLM 호출.
- 끊김 자동 재시도·재확인 통화·남은 질문만 재통화하는 새 정책.
- 실제 발신 허용 범위 확대. 기존 지정 시험 계정/학원/번호와 발신 제한은 유지한다.
