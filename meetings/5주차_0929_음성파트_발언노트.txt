[1분 요약]

음성 도구 비교 끝냈고 1순위는 Vapi입니다. 고르는 기준이 기능이나
가격이 아니라 070 회선을 붙일 수 있느냐였습니다. 국내 070은 G.711
코덱이라 이걸 받아주는 Vapi·Retell·LiveKit·ElevenLabs만 후보에
남고, OpenAI Realtime은 직결이 안 됩니다. 어제 Vapi에 한국어
에이전트를 실제로 만들어 브라우저 통화까지 확인했습니다. 다만 무료
등급에서는 전화망 기능이 막혀서, 실제 발신은 결제 계정이 필요합니다.

그리고 회선 요구 사양은 지금 바로 넘길 수 있습니다.


-----------------------------------------------
1. 회선 요구 사양 (오늘 제출 / 팀 문서상 "회의 전" 기한 항목)
-----------------------------------------------

o SIP 트렁크 방식, 아웃바운드 발신 가능 (수신은 당장 불필요)
o 코덱 G.711 A-law — 국내 회선 표준이고 Vapi·Retell 모두 이 기준으로 수용
o 인증은 IP 허용 등록이 아니라 digest(ID/비밀번호) 방식
   - Retell은 고정 IP가 없어 IP 등록 방식이면 연결 불가
   - Vapi 공식 문서도 IP 인증을 권장하지 않음 (라우팅 문제)
o TLS 시그널링·SRTP 지원 여부 확인 필요
o 동시 통화 최소 2회선, 월 발신 100분 이상
o 국내 사업자 기준 개인 요금제 월 1.9만 원(발신 100분),
  비즈니스 월 9.9만 원(발신 1,000분), 3일 무료 체험 있는 곳 존재

[OpenAI Realtime을 뺀 이유]
Realtime의 SIP는 Opus + TLS + SDES-SRTP를 요구. 국내 070은 G.711이라
직결 불가. 중간 변환 게이트웨이를 우리가 만들어야 해서 제외.


-----------------------------------------------
2. 도구 비교 결과 (7개 후보)
-----------------------------------------------

Vapi / Retell / ElevenLabs Agents / OpenAI Realtime / LiveKit /
리턴제로 RTZR / 네이버 CLOVA 를 기능·한국어·070 연동·가격·체험
가능 여부로 비교.

o 1순위 Vapi
  - STT·LLM·TTS를 따로 끼울 수 있어 한국어 엔진 비교가 가능
  - 구간별 지연을 따로 볼 수 있음 → 1.5초 목표 검증에 필수
  - 요금: 플랫폼 $0.05/분 + 구성요소 별도, 합계 $0.10~0.30/분
  - 무료 크레딧 $5, 동시 통화 4회선

o 2순위 Retell — 통신까지 번들($0.07~0.31/분), 설정·정산 단순.
  대신 엔진 교체가 어려워 비교 실험은 포기해야 함

o 3순위 LiveKit SIP 게이트웨이 + OpenAI Realtime — 지연·자연스러움은
  유리하나 G.711↔Opus 변환을 우리가 책임져야 함

o 국내 STT는 이번 학기 사용 불가
  - 리턴제로: 한국어 통화 인식 최상급이나 API 가격 비공개,
    biz@rtzr.ai 영업 문의 필요 → 지난 회의에서 우려한 내용이 사실로 확인
  - 네이버 CLOVA: 국내 엔진 중 유일하게 셀프 가입으로 바로 사용 가능

3. 근거 자료 (공식 문서)
-----------------------------------------------

[Vapi를 070에 연결 가능한 근거]
Vapi 공식 SIP 문서:
"Custom 'BYO' SIP Trunk: Allows integration with any SIP provider.
 You simply provide the SIP gateway address and the necessary
 authentication details."
- 발신은 byo-sip-trunk 타입 자격증명 생성 후 번호 연결
- 인증은 authUsername / authPassword (digest)
- IP 기반 인증은 문서에서 비권장
- 예시 제공자로 Telnyx, Plivo, Zadarma 명시
- 리전은 API와 SIP 호스트를 맞춰야 함 (US: api.vapi.ai + sip.vapi.ai)
→ https://docs.vapi.ai/advanced/sip/sip-trunk

[내부 DB 연결 가능한 근거]
Function tool(대시보드 Custom Tool)로 통화 중 우리 서버 API 호출:
- 우리가 HTTPS 엔드포인트와 파라미터 JSON 스키마를 등록
- 통화 중 AI가 도구를 호출하면 Vapi가 우리 서버로 POST
  (toolCallList에 함수명·인자·통화 컨텍스트 포함)
- 우리 서버는 { "results": [{ "toolCallId": "...", "result": "..." }] }
  형식으로 응답
- 도구 단위 server URL과 별개로 통화 이벤트·종료 리포트용
  assistant 단위 웹훅 존재
→ MySQL 저장은 우리 서버가 담당하므로 Vapi가 DB에 직접 붙을 필요 없음
→ https://docs.vapi.ai/tools/custom-tools

[기업 사용 가능한 근거]
Vapi Trust Center 공개:
- SOC 2 Type II 연례 심사 완료 (2025.7.1~2026.7.31), SOC 3 공개 리포트
- HIPAA, GDPR, PCI DSS v4.0.1, CCPA
- 감사 로깅, 저장 데이터 암호화, Zero Trust, 침투 테스트 리포트, 사이버보험
- 검토·이용 기업: New York Life, Spring Venture Group, Mindtickle,
  Independent Bank 등
→ https://security.vapi.ai/

4. 어제 실제로 해본 것
-----------------------------------------------

o Vapi에 한국어 아웃바운드 에이전트 생성, 브라우저 통화 동작 확인
o 프롬프트에 포함한 것
  - 학원의신 AI 상담원임을 통화 시작 시 고지
  - 한 번에 한 가지씩 질문, 모호하면 짧게 재확인
  - 모르는 정보는 추측·생성 금지
  - 통화 말미에 핵심 내용 요약 확인
  - 개인정보 요구 시 임의 응답 금지, 등록·결제 임의 약속 금지
o 무료 등급의 한계 확인
  - Telnyx 무료 계정은 AI 제품만 허용, DTMF 등 전화망 기능 잠김(실제 차단 확인)
  - 학원이 ARS를 쓰면 번호 입력이 필요한데 이는 결제 계정 필요

5. API 요구 항목 (팀 문서안에 동의 + 3개 추가)
-----------------------------------------------

동의: answered + yes_no + detail 구조, 지연 평균·p95·턴 수,
      고지 재생 여부, 통화 녹음 URL, 상담 수락 여부, 가능 시간,
      미확인 항목 목록

추가 요청:
o attempt_id 를 call_id 와 분리 — 재시도 이력 연결용
o 상태 이벤트에 event_id — 중복 수신 시 결과 1건만 저장(멱등)
o 답변 상태에 "미확인"과 "범위 밖" 구분
   - "모른다"와 "그건 원장님께 여쭤보셔야" 는 다른 결과

6. 테스트 기준 (VO 체계에 5개 추가 제안)
-----------------------------------------------

o 지연 정의: 상대 발화 종료 시점 → AI 첫 오디오 출력 시점,
  평균과 p95 동시 기록, 합격 판정은 p95 기준 제안
o 팀 문서 VO-01~07에 없는 케이스 추가 제안
  - 무응답 (벨만 울림 → 부재중 처리 후 재시도 큐)
  - 거절 (수업 중 → 상담 가능 시간 확보 또는 재통화 요청 분류)
  - 부분 답변 (하나만 답 → 나머지는 미확인, 추측 금지)
  - 범위 밖 질문 (확인 후 회신으로 응답)
  - 중복 이벤트 (결과 1건만 저장)
o 비결정성 판정: 문구가 아니라 슬롯 값으로 판정
  (예: 통학 가능 = 예 / 아니오 / 미확인)
